Never join unrestricted fields using a delimiter that those fields may contain.” Existing IDs require an explicit identity-version migration.
66. **[medium, U] Short-hash collisions are indistinguishable from duplicates. Location: LIFE.md §6; short identifiers throughout the schema.** INSERT OR IGNORE can silently discard a different item whose shortened digest collides. **Replacement:** “Store the complete canonical identity and full SHA-256 beside every shortened display ID. On an ID conflict, compare full identities. Exact equality is deduplication; inequality is an integrity hold and never an ignored insertion.”
67. **[medium, U] Identity normalization differs across artifacts. Location: norm_text, command identity, focus identity, fact identity.** Some identities normalize NFC/whitespace/case, while others hash original text, quote text, or file bytes. The exact pre-hash representation is not consistently defined. **Replacement:** “Publish one identity registry specifying, for each identifier, ordered fields, byte encoding, normalization, case treatment, newline treatment, and hash truncation. Hash original file bytes where byte identity is intended; do not let text-mode newline conversion change that identity.”
68. **[medium, U] Queue order lacks a final tie-breaker and starvation rule. Location: LIFE.md §6.** Second-resolution updated_at produces ties, and continuous high-priority arrivals can indefinitely delay lower-priority work. **Replacement:** “The final stable key is item_id ASC. Record a monotonic enqueue sequence for requeue order. Every tenth successful selection from a cell serves its oldest eligible item regardless of priority; all safety gates still apply.”
69. **[high, U] Retry domains share insufficiently defined counters. Location: items.attempts; LIFE.md §§4, 7.5, 7.9, 8.** Guard faults, non-submissions, infrastructure runs, reviewer revisions, and model escalation have different limits but no separate counter definitions. **Replacement:** “Persist separate counters for stage faults, submission attempts, executed agent runs, infrastructure retries, review revisions, and model-rung attempts. Each counter has one increment event and one reset event. Request IDs use the monotonic submission-attempt counter only.”
70. **[medium, U] Failure-streak reset semantics are undefined. Location: cells.failures_in_a_row; lifecycle rules.** It is unclear whether a successful stage, abstention, operator handoff, ineligible experiment, or completed logical item resets the streak. **Replacement:** “Only successful completion of a logical item resets the consecutive semantic-failure streak. Intermediate stages do not reset it. Infrastructure outcomes, abstentions, and operator handoffs neither increment nor reset it. Each item can increment the streak at most once.”
71. **[medium, U] Ladder windows can repeatedly trigger tuning. Location: LIFE.md §8.** The text does not say whether the ten-outcome window is cleared after a rung change. An unchanged window can promote or demote again immediately. **Replacement:** “Evaluate tuning only after appending a terminal logical-program outcome to a ten-entry window. A rung change clears the window. At a ladder boundary, retain the boundary rung and clear the triggering window. Record exactly one rung event per evaluation.”
72. **[high, U] Rungs are not reconciled with the current ladder. Location: cell_programs, items.rung_extra, organs_problems.** Database rungs allow 0..4, while ladders allow one to three models. Release changes can shorten or reorder ladders. **Replacement:** “Persist model identity with rung state. Before admission, map that identity into the active ladder; if absent, reset to rung 0 with an event. Effective rung is bounded by len(ladder)-1. Stage changes clear item-specific escalation.”
73. **[high, D] Malformed output and message substrings can evade semantic accounting. Location: LIFE.md §8 outcome classification.** Every no-JSON result becomes infrastructure, and an unspecified text pattern can classify model-derived error text as infrastructure. A broken program can retry indefinitely without accumulating failures. **Replacement:** “Only structured executor-generated error codes establish infrastructure failure. Invalid output from an otherwise completed execution is protocol_failure and consumes its finite retry allowance. Untrusted diagnostic text never determines retry class.”
74. **[high, U] Model and research budgets lack durable pre-launch charging. Location: calls, budget, program contract.** Recording usage after completion loses charges when a process starts and the coordinator crashes before collection. **Replacement:** “Atomically reserve the program-run budget before launch. Persist the operation’s maximum model-call allowance and collect actual usage separately. A started or launch-unknown operation remains charged. Refund only an execution that is authoritatively proven never to have started.”
75. **[medium, D] Budget helpers can cross UTC midnight between statements. Location: budget_add; metric_add.** They compute the day more than once. A row can be created for the previous day and updated for the next day, losing the increment. **Replacement:** “Capture the accounting day once from the operation’s admission timestamp and pass it through every insert and update in the same transaction. Completion metrics use their separately specified completion day.”
76. **[medium, D] Counter helpers accept invalid increments. Location: budget_add; metric_add; counter schemas.** Negative increments can reduce budgets, and argument validation relies on assertions for column names. **Replacement:** “Validate column membership with ordinary runtime checks. Require type(n) is int and n >= 0. Add nonnegative database constraints to every budget and metric counter. Budget refunds use a separate audited operation tied to a reservation.”
77. **[medium, U] Efficiency units and minimum-sample calculation are undefined. Location: spawn/PROTOCOL.md eligibility rule 10.** “Fewer than 20 runs” may mean raw runs or the weighted denominator; retries and reproduction calls may or may not count. **Replacement:** “Let cost units equal all admitted genome/research runs plus three times all admitted agent runs for that organ, including failures and reproduction. Evaluate the ratio only when cost units are at least 20 over the two immediately preceding complete UTC days. A zero denominator does not establish efficiency.”
78. **[medium, U] Administrative completion can inflate useful-work efficiency. Location: LIFE.md §§7.2, 7.7; metrics.** Exhausted questions and ineligible experiments become done, although they may produce no useful result. This can reward cheap rejection over productive work. **Replacement:** “Track items_terminal separately from useful_outputs. Division efficiency uses useful outputs: accepted source contributions, validated claims, ready patches/proposals, applied migrations, or valid measurements, as appropriate to the organ. Administrative completion does not count as useful output.”
79. **[medium, U] Guard retry does not define recovery after partial effects. Location: LIFE.md §4, Tick.guard.** Returning an item to the queue after an exception can repeat a migration, artifact publication, or external submission that already occurred. **Replacement:** “Guard retries only pure operations directly. Effectful stages first reconcile their durable operation record. They resume from the last committed phase and never repeat a completed external effect merely because a later bookkeeping step failed.”
80. **[medium, U] Infrastructure retries have no eventual escalation policy. Location: LIFE.md §8.** A permanently missing model or malformed platform response can consume repeated runs forever while never affecting the cell. **Replacement:** “For each item-stage and node, allow three infrastructure launches in a rolling hour. Thereafter suspend that stage, open one diagnostic notice, and require either a successful readiness probe or operator release. Suspension consumes no additional model budget.”

## Reproduction and lifecycle

81. **[high, D] The open-division index does not enforce the fleet-wide limit. Location: db/life.sql, divisions_one_open.** A unique index on parent_id permits one open division for every different parent, not one globally. **Replacement:** “Use a unique partial index on a constant expression for rows whose stage is open, or a singleton division-reservation row. The database must reject a second open division regardless of parent.”
82. **[medium, U] Population caps do not distinguish provisional and committed rows. Location: spawn/PROTOCOL.md eligibility rules 5–6.** Organ capacity uses net +1; global capacity uses +2. Under the latter rule, a committed population of 15 cannot divide to 16 even though the parent retires atomically. **Replacement:** “Population caps apply to committed nonretired cells plus outstanding birth reservations. One division reserves net one population slot and two daily births. If temporary-row headroom is intentionally required instead, explicitly document the resulting effective population ceiling.”
83. **[high, U] Division commit lacks a complete revalidation rule. Location: spawn/PROTOCOL.md §§1–2.** Node readiness, control state, daily budget, population, and parent state can change during a multi-tick division. **Replacement:** “Immediately before commit, in the admission transaction, revalidate every eligibility predicate and reservation against current state. A failed predicate aborts or suspends according to a closed reason table. Start-time eligibility is never sufficient for a later birth.”
84. **[high, U] Workspace creation is outside a recoverable birth protocol. Location: spawn/PROTOCOL.md §§2–3.** Children can be born and the parent retired even when a clone fails, leaving both successors unable to perform their agent stages. **Replacement:** “Prepare and validate both child workspaces before activating either child. Persist preparation phases and intended paths. Commit both births, item transfers, and parent retirement only after both workspaces are ready. Failed preparation leaves the parent active and never exposes half a division.”
85. **[high, D] Workspace and request identities omit depth. Location: child identity; agent request-ID formula.** Cell IDs contain organ, depth, and an eight-hex suffix, but workspaces and request IDs omit depth. Distinct cells with the same suffix can alias the same workspace and request namespace. **Replacement:** “Use the complete canonical cell ID, or a full collision-checked cell UUID, in workspace ownership and request identity. Enforce unique workspace ownership in the registry. Existing-directory equality is never treated as proof that the directory belongs to the new cell.”
86. **[high, U] Retired parents can retain work that needs later stages. Location: spawn/PROTOCOL.md §2; LIFE.md dispatch.** Running work remains attached to the retired parent, but completed agent runs need gate/apply stages, and ordinary dispatch assigns only active cells. **Replacement:** “Introduce an explicit draining lifecycle state, or transfer post-execution stage ownership to a child after terminal collection. A parent cannot become fully retired while it owns any item requiring future processing. Its execution history remains immutable.”
87. **[high, U] Agent children may clone a parent with unfinished work. Location: spawn/PROTOCOL.md §3.** Selfdev/database children clone the parent workspace, while the protocol permits the parent to retain a live run. It does not define which committed or uncommitted state is inherited. **Replacement:** “Child workspaces are constructed from an explicitly recorded clean base commit and approved input manifest, never the parent’s mutable working tree. Parent in-flight outputs are collected into their own bundles and are not inherited implicitly.”
88. **[medium, U] Division snapshot ordering is incomplete. Location: spawn/PROTOCOL.md §2; example division.** “First 12,” “first 16,” and snapshot items need one stable ordering, particularly after requeueing or priority updates. **Replacement:** “At division start, persist the ordered item-ID snapshot using the canonical queue ordering. Sampling and model assignment use that saved order. Later item updates do not reorder the snapshot. Commit considers only items still owned by the parent and eligible for transfer.”
89. **[medium, U] Failed assignments need a durable completion marker. Location: divisions.assigned; assignment protocol.** The stored map contains only "a" or "b". Without a persisted fallback result or attempted marker, a failed assignment can be retried on every tick instead of advancing. **Replacement:** “On semantic assignment failure, immediately persist the parity-selected side plus assignment_method='fallback'. An assigned or fallback-completed item is never sent to the model again within that division.”
90. **[medium, U] Division identity, expiry, and cleanup are incomplete. Location: divisions schema; spawn/PROTOCOL.md.** The division-ID algorithm is absent, “older than three hours” lacks an exact boundary and clock rule, and abandoned preparation directories have no cleanup state. **Replacement:** “Assign a collision-checked operation UUID at start. Expire when elapsed monotonic duration reaches 10,800 seconds. Terminalization records the exact reason, releases reservations once, restores parent dispatch eligibility when appropriate, and records every prepared workspace for operator-approved cleanup.”
91. **[medium, D] Different strings do not prove narrower foci. Location: genome/reproduce.sym.** The checks establish only textual inequality. “Research everything carefully” and “research everything thoroughly” pass without constituting a narrower, exhaustive partition. **Replacement:** “Textual checks establish distinct labels only. Operational specialization is defined by the persisted partition of item IDs. Do not claim semantic narrowing unless an independently specified coverage/overlap criterion is met. Empty or duplicate operational partitions are refused.”
92. **[medium, D] Future dispatch ignores the specialization reproduction created. Location: LIFE.md §4 dispatch; reproduction protocol.** New items go to the least-loaded active cell, regardless of focus. A ceramic foams child can immediately receive polymer-fibre work. **Replacement:** “Future items are routed through a bounded assignment operation over active sibling foci, with deterministic fallback and persisted routing evidence. Load balancing chooses among eligible matching cells; it does not silently replace focus-based assignment.”
93. **[medium, U] Disabled organs can still accumulate reproduction pressure. Location: selfdev gating; division eligibility.** SELFDEV_ARMED gates agent starts, but division eligibility does not include it. Queued lessons can trigger selfdev reproduction while self-development is disabled. **Replacement:** “An organ whose execution authorization is disabled does not accumulate backlog-sustain credit, start divisions, or consume reproducer calls. Its queued items remain visible and retain their original age.”
94. **[high, U] Quarantining the last active cell leaves an organ unschedulable. Location: spawn/PROTOCOL.md endings.** Apoptosis protects the last active cell; quarantine does not. Its queued items return to an organ with no eligible worker. **Replacement:** “Last-cell quarantine is permitted for safety but sets the organ to suspended_no_active_cell, opens a mandatory notice, and stops routing new executable work into an invisible dead end. Recovery requires a validated release-cell or replacement-cell operation.”
95. **[high, U] release-cell and retire lack complete transitions. Location: LIFE.md §15; spawn endings.** The reset of failure counters, rung windows, queued items, open divisions, live runs, and workspace state is unspecified. **Replacement:** “Define each command’s preconditions and postconditions over every affected table. Release clears the quarantine streak only after readiness and workspace validation. Retire cancels or drains owned executions, aborts open division intent, and transfers queued work atomically; force never discards unresolved execution ownership.”
96. **[medium, U] Missing workspaces and orphaned items have no recovery rule. Location: spawn/PROTOCOL.md §3; dispatch.** “Wait until the workspace exists” does not establish who recreates it, what content is valid, or whether a mere directory is sufficient. **Replacement:** “Workspace recovery is an idempotent controller operation using the recorded base and input manifest. A directory counts as ready only after identity, repository, cleanliness, and manifest checks pass. Orphaned queued items are reassigned only after their former execution ownership is settled.”
97. **[medium, U] Child rung inheritance and release semantics are incomplete. Location: cells.release; spawn inheritance.** A parent’s rung indices may refer to an older ladder while children are born under a newer active release. **Replacement:** “Birth records retain the parent’s birth-release lineage separately from the child’s initial execution release. Inherited tuning is translated by model identity into that execution release. Unmappable entries reset to rung 0; outcome windows start empty.”
98. **[medium, U] Child placement counts cells but not committed workload reservations. Location: division eligibility rule 11.** A node below four cells can still have an unresolved agent run or benchmark reservation and insufficient execution capacity. **Replacement:** “Placement checks both population reservations and executor resource reservations. Child B must have an admissible execution profile on the chosen node, not merely an available cell-count slot. Revalidate the selected node at commit.”
99. **[medium, U] Division fairness across organs has no progress guarantee. Location: spawn/PROTOCOL.md §1.** Fixed cell-ID scanning can repeatedly favor lexically earlier organs when birth budgets and the single open division are scarce. **Replacement:** “Choose the eligible organ least recently granted a division, then its oldest eligible cell, then cell ID. Persist the selection cursor. A failed or aborted attempt updates the attempt cursor but does not erase that organ’s backlog evidence.”

## Inbox, research, and knowledge

100. **[medium, U] Inbox filename grammar and uniqueness are incomplete. Location: LIFE.md §6.** Slug characters, maximum length, timestamp validity, ordering, and same-second collision handling are absent. **Replacement:** “Use a valid UTC timestamp followed by a lowercase ASCII slug and a random 16-hex suffix. Create with exclusive creation, never overwrite. Ingestion order is filename ascending. Same text submitted twice receives distinct filenames and command IDs.”
101. **[high, U] Inbox ingestion is not a recoverable claim protocol. Location: LIFE.md §6.** Validation, hashing, database insertion, and movement to inbox-done can fail between steps or race an operator rewriting a file. **Replacement:** “Atomically claim the file into a private processing directory, open without following links, verify operator and regular-file status on the opened descriptor, read at most 4001 bytes, and hash those exact bytes. Commit the command and claim identity before final movement. Recovery completes or safely refuses each claimed file exactly once.”
102. **[medium, U] Command routing extraction and route-specific limits are incomplete. Location: LIFE.md §7.1.** Multiple test IDs, multiple genome names, short database requests, and overlong compute/selfdev inputs have no exact handling. **Replacement:** “Use closed parsers for each route. 103. **[medium, U] Deduplicated work loses per-command ownership. The second command’s outcome becomes unclear. **Replacement:** “Maintain a many-to-many command-to-item association. 104. **[medium, U] Final command delivery is not defined. Location: command stage; commands.state.** The route handler sets dispatched or operator, but there is no specified transition to done/failed when downstream work finishes. **Replacement:** “A command becomes done only when all required associated items have reached acceptable terminal states and its result artifact is published. 105. **[medium, U] Source-key length is not contracted between normalization and storage. 106. **[medium, U] Research result parsing is incomplete. Location: LIFE.md §§7.2, 17.** The result is described as a list containing sources, but source-entry structure, multiple records, malformed entries, duplicate entries within a run, and partial-success handling are unspecified. **Replacement:** “Require exactly one validated research record for the requested model and node. Define source-entry keys and types. Process entries in their returned order, deduplicate within the response before global insertion, and record rejected-entry counts and reasons without failing already validated entries.”
107. **[high, U] Research does not inherit the genome model-call limits. Location: research invocation; program-run contract.** --tools 8 limits tool actions, not necessarily model turns, token generation, answer size, or retained reports. **Replacement:** “The research adapter must enforce a maximum of 12 model calls, eight tool actions, 1024 generated tokens per model call, a 900-second total deadline, and capped response/report bytes. Refuse admission if the installed research backend cannot expose and enforce those limits.”
108. **[medium, U] The nine-source limit needs a remaining-quota clamp. Location: LIFE.md §7.2.** A question with seven or eight recorded sources can otherwise admit three more. **Replacement:** “The maximum new sources accepted from a run is min(3, 9-found). Increment found only for committed question-source associations counted by this limit. Any positive accepted count resets dry_runs to zero; a zero count increments it once.”
109. **[medium, D] One question_id per source loses shared provenance. Location: sources schema.** A globally deduplicated source can be relevant to several questions, but the schema records only its first question. Later questions can be exhausted despite having relevant previously known sources. **Replacement:** “Keep one global source identity and a separate question_sources(question_id, source_key, discovered_at, discovery_run_id) relation. Reusing a known source creates an association without fetching or inserting a duplicate source.”
110. **[medium, U] Global dedup has no refresh or failed-fetch recovery policy. Location: LIFE.md §7.2; source fetch states.** Once a URL is inserted, failed fetches and subsequently changed content have no specified route back to useful processing. **Replacement:** “Separate source identity from immutable snapshot versions. Retry transient fetch failure at most three times with persisted delays. Content refresh occurs only under an explicit operator refresh request or approved agenda entry; identical content hashes do not create duplicate snapshots.”
111. **[high, U] Fetch safety lacks a complete resource and connection contract. Location: LIFE.md §7.3.** A 6000-character retained result does not bound downloaded bytes, decompression, parser memory, redirect count, or the relationship between address validation and the actual connection. **Replacement:** “The trusted fetch adapter enforces explicit wire-byte, decoded-byte, redirect, parser-memory, and total-time limits; pins each connection to an address validated for that hop; and returns typed refusal reasons. These guarantees must be tested against the installed safe-fetch implementation, not inferred from its name.”
112. **[medium, U] Snapshot identity and fetch outcome mapping are incomplete. Location: LIFE.md §7.3; sources.** The <16hex>.txt derivation and the mapping from timeout, refusal, empty extraction, parse failure, and interrupted write into fetch states are not specified. **Replacement:** “Name snapshots by a full content digest, store source identity separately, and publish only after complete validation and durable write. Define one closed fetch-outcome table mapping each adapter result to source state, item state, retry eligibility, and notice behavior.”
113. **[medium, D] The two quote checks use different semantics. Location: extract-source.sym; LIFE.md §7.3.** The genome describes NFC, whole-word, whitespace-normalized matching; the coordinator description specifies whitespace-collapsed substring matching. These can disagree on Unicode and word boundaries. **Replacement:** “Use one shared quote-verification function in both paths, with identical normalization and boundary rules. Persist the original quote and the normalization version. A coordinator check may not be weaker than the kernel check it claims to repeat.”
114. **[medium, U] Fact publication and downstream item creation lack atomicity. Location: digest stages.** A crash after inserting knowledge but before creating the lesson, or after creating the lesson but before advancing the source item, can lose or duplicate downstream work. **Replacement:** “Knowledge insertion, source-item advancement, and downstream-item association occur in one registry transaction using deterministic identities. Re-execution compares existing records for equality and resumes the missing transition without repeating a completed model call.”
115. **[medium, U] Unreviewed and superseded claims have no operational consequences. Location: knowledge.claim_status; digest routing.** The schema distinguishes these states, but does not define who changes them or what happens to pending lessons and requests derived from a superseded claim. **Replacement:** “Only an operator operation or an explicitly approved verification workflow changes claim status. Derived artifacts retain the source claim status and provenance. Supersession blocks unstarted derived actions pending reevaluation and never silently rewrites already published evidence.”
116. **[medium, U] Research completion does not distinguish discovery from useful evidence. Location: LIFE.md §§7.2–7.3.** A question can reach its source limit while every source is empty, refused, or unsupported. **Replacement:** “Question results separately report discovered sources, fetched snapshots, quote-verified claims, and refused/failed sources. Reaching the discovery limit ends discovery only. The command result is evidence_found, no_usable_evidence, or incomplete, according to explicit counts; it is not automatically an answered question.”
117. **[medium, U] Program output envelopes and binding checks are unspecified. Location: LIFE.md §8.** “Status done and exactly one returned record” does not identify the JSON path, supported envelope version, exact field set, or required equality of echoed subject IDs. **Replacement:** “Each program has a closed output schema and binding checks against its input manifest. Exactly one record must appear at the documented envelope path. Wrong subject/source/finding IDs, extra records, extra keys, and invalid field types are protocol failures.”
118. **[medium, U] Model identity and execution settings are not pinned. Location: ladders; Ollama limits.** Model tags and two options do not define an immutable model artifact, context size, prompt template, or the remaining runtime settings relevant to reproducibility and memory. **Replacement:** “Each admitted model entry records its artifact digest, approved runtime version, context limit, prompt-template identity, and complete allowed option set. Tag resolution must match that manifest before execution. A changed digest is a new model revision requiring explicit admission.”
119. **[medium, U] Typed success is not distinguished from task success. Location: LIFE.md §§1, 8.** An enum-valid classification or syntactically valid proposal can still be wrong. The current “done” and tuning terminology risks treating structural validity as demonstrated effectiveness. **Replacement:** “Record protocol_valid, task_accepted, and useful_outcome separately. Type/range checks establish only protocol validity. Rung tuning and self-improvement claims identify the exact downstream acceptance metric used; they do not infer correctness from a well-formed answer alone.”

126. **[medium, D] Documentation scope has inconsistent recursive meaning. 127. **[high, D] The module-location check happens after importing the module. 128. **[high, D] A __file__ prefix is not a containment proof. Location: checks/devcheck-gate.sh.** Candidate code can affect __file__, and lexical paths can traverse symlinked ancestors. **Replacement:** “Validate filesystem objects through canonical descriptor-relative traversal beneath the sandbox checkout root. It never defines which baseline and diff command determine the accepted patch. **Replacement:** “The gate operates on a clean checkout of the recorded baseline plus the exact candidate patch bytes. 133. **[high, U] Git object types and metadata changes are not constrained. Location: patch gate and apply.** Symlinks, submodules, executable-bit changes, renames, binary patches, unusual filenames, and repository metadata have no explicit policy. **Replacement:** “Automatic patch preparation accepts only regular text files with unchanged modes and canonical UTF-8 repository-relative names. 181. **[high, U] Migration execution has no complete resource contract. Location: LIFE.md §7.8.** Index creation, constraint validation, or hostile snapshot input can consume unbounded work relative to the tick’s available time. **Replacement:** “Validation runs in a sandbox with a 30-second wall limit and 512 MiB memory limit. 196. **[medium, D] Malformed ARMED text escapes the intended disarmed fallback. Location: control_state.** Reading ASCII can raise a decoding error, but only OSError is caught. **Replacement:** “ARMED is a bounded regular file containing exactly one valid boot UUID plus an optional final newline. 198. **[high, D] The documented restore procedure is unsafe. Location: LIFE.md §12.** Stopping the timer and copying a database over the file does not establish that the active tick, controller, database connections, or remote work are quiescent. 199. **[high, U] Storage accounting does not cover all growth locations.
