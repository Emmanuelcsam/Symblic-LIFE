**U** marks an undefined or ambiguous contract. **D** marks a concrete contradiction, missing implementation, or code defect. The proposed limits, adapters, and replacement mechanisms below are design changes, not claims that the existing platform already supports them. BRIEF.md is treated as authoritative.

## Architecture and platform contracts

1. **Medium · U — LIFE.md, author’s note and platform references.** A verification date does not identify the implementation against which the kit was checked. LIMITS, DEFAULTS, VERBS, engine admission, flags, and formal-language semantics could differ between authoring and execution. **Adopt:** “Startup requires an immutable compatibility manifest containing the platform commit, relevant file hashes, complete normalized policy defaults, supported command interfaces, and model-launch capabilities. Missing or mismatched entries block startup. A safety conflict between BRIEF.md and this kit is a startup error, not permission to choose either interpretation.”
2. **High · D — LIFE.md §1; bin/life-spawn-tick.py, module contract.** LIFE defines a cell as one statement inside a run, but the spawner defines a cell as an entire autogen run. A five-statement database run therefore has either one cell or five, changing lineage, reproduction, failure counts, and budgets. **Adopt:** “An organ owns runs; a run contains statement cells; a cell is identified by (run_id, statement_index); a generation and attempt are execution events, not new cells. Reproduction creates explicitly identified successor cells inside newly admitted runs.” Update every counter and foreign key to this ontology.
3. **High · U — LIFE.md §1 and §4; organs/*.lines.txt.** No supplied organ statement invokes reproduce.sym, schedules a reproducer, obtains authoritative metrics, or converts its returned plan into queue records. Installing the timer only consumes records; it does not create them. **Adopt:** “After each committed cell-generation event, a coordinator hook schedules exactly one reproducer evaluation keyed by that event ID. Its result is consumed by a code-owned record builder. Repeated delivery of the same event cannot create a second evaluation or proposal.” Until that hook exists, label reproduction unimplemented.
4. **High · U — LIFE.md §1, role separation.** Separate descriptions do not prevent a worker from writing spawn records, invoking symblic-task start, changing its metrics, or impersonating its reproducer. Both agents appear to share ordinary filesystem and tool access. **Adopt:** “Workers cannot invoke lifecycle operations or write coordinator-owned state. Reproducers receive read-only evidence and can return proposals only. The coordinator alone possesses submission capability. Role identity is assigned by the launcher and cannot be supplied in an artifact.”
5. **High · D — LIFE.md §3, “When a CLI agent is allowed”; bin/life-seed.sh.** CLI agents are supposedly permitted only in codebase, selfdev, and database, yet every organ is launched through start() with --engine agy. **Adopt:** “Existing autogen lanes necessarily execute CLI agents. Either explicitly authorize that wrapper for the listed organs and budget it, or replace typed-only organ loops with deterministic coordinator code that invokes registered worker node model jobs. Do not describe the current ten autogen launches as a three-organ CLI exception.”
6. **High · D — LIFE.md §2; bin/life-seed.sh, metabolism and heartbeat launches.** Metabolism and heartbeat are agy tasks placed on the host. Calling those tasks “i/o only” does not make them non-agent processes. This contradicts BRIEF.md’s requirement that agent/model work run on the worker nodes. **Adopt:** “Metabolism and heartbeat are deterministic programs running on the host, with no CLI-agent invocation. They are not autogen runs and do not appear in the model-lane seed list.” Update the stated number of seed runs accordingly.
7. **Medium · D — LIFE.md §3 versus §11 gap 4.** Section 3 permits delegate templates for cell work; §11 expressly prohibits delegate inside LIFE v1. **Adopt:** “LIFE v1 does not use bin/symblic delegate. Remove it from the active model ladder, worker instructions, and examples. It may remain only in a clearly labeled future-capability section.”
8. **High · D — LIFE.md §11 gap 3; policies/database.json; bin/life-seed.sh.** The kit states that remote handoff is unsupported, then launches database on node-a with generations: 2 and --handoff 2. “Can be reconsidered” is not an execution rule. **Adopt:** “worker node runs use the platform’s verified no-successor-handoff setting. Any requested remote handoff is rejected during validation and startup. Database work uses separately verifiable statements and supported decomposition only.” Do not invent the disabling flag or value without checking the pinned platform contract.
9. **High · U — LIFE.md §3, engine escalation.** Membership in ENGINES ∩ ADMITTED_ENGINES does not establish that an engine can launch on a particular worker node, has an authenticated registered launch path, or will remain on that node. The stated copilot placement is especially incompatible with the worker node-only rule. **Adopt:** “Engine selection uses an operator-approved (node, engine, registered_launcher) capability matrix. Every escalation repeats that check. An unavailable combination produces INFRASTRUCTURE_HOLD; it never migrates to the host, copies credentials, or creates an SSH bypass.”
10. **High · U — LIFE.md §11 gap 2; genome/*.sym.** The helper invocation lacks exact input binding, output serialization, exit handling, executable location, and return transport. Naming bin/symblic run … --by … does not explain how a fresh agent supplies given values or obtains a machine-readable record. **Adopt:** “Each genome has a versioned adapter with an input JSON schema, output JSON schema, fixed executable invocation, expected exit classifications, and registered worker node transport. The adapter rejects unexpected stdout and writes results to one task-scoped artifact.”
11. **High · U — All organ statements; bin/life-spawn-tick.py, submission.** Statements name the host absolute paths while execution occurs on worker nodes and verification occurs in a home staging checkout. No mapping says whether those paths refer to a remote mirror, a shared mount, a staging snapshot, or the live workspace. **Adopt:** “Every job receives a manifest mapping logical artifact paths to its isolated execution paths and home verification paths. Absolute paths in generated statements are resolved for that job before admission. Direct writes to the host workspace from worker node workers are forbidden.”
12. **High · U — organs/*.lines.txt, implicit dependencies.** Fresh agents are told to use “the master script,” “the command classifier,” “the source fact extractor,” “the index,” or “the same” schema without receiving exact dependency paths and versions. **Adopt:** “Each statement names an immutable task-input manifest containing all permitted input files, their hashes, the applicable schema, the exact helper adapter, and the acceptance contract. Missing dependencies yield BLOCKED_INPUT; agents must not infer them from earlier statements or search unrestricted directories.”
13. **Medium · D — LIFE.md §3; genome/*.sym.** The claimed cheapest-first ladder is not implemented. Routing and reproduction begin with fixed 4B asks; the code does not try a smaller model, evaluate a failure, and advance a rung. **Adopt:** “Either replace the ladder claim with the actual fixed model mapping, or implement a deterministic per-operation ladder specifying ordered model IDs, escalation-triggering errors, maximum calls, and terminal outcome. Cloud-engine rotation is not a local-model ladder.”
14. **High · U — LIFE.md §2–3, model inventory.** Model tags and parameter counts do not specify immutable weights, quantization, context allocation, resident memory, or availability. “Installed on node-h” does not prove compatibility with its stated 3 GiB cap. **Adopt:** “The model manifest records exact model digest, quantization, artifact bytes, maximum context, output-token limit, measured reservation requirement, and eligible nodes. Missing models are held for operator action; LIFE does not pull models, substitute tags, or increase memory caps automatically.”
15. **Medium · U — genome/*.sym, ask, votes, retries, and ensure.** The kit does not define how retries interact with voting, whether a failed ensure reruns one ask or the whole program, how ties are resolved, or what happens after exhaustion. **Adopt:** “The compatibility manifest fixes these semantics. A typed decision has a maximum of 12 model calls, each with an explicit token and elapsed-time budget. Every call, including votes and repair attempts, consumes that budget. Exhaustion returns a typed failure and no executable proposal.”
16. **High · U — LIFE.md §3 and §6, shared formal-language calls.** A lane can hold a node reservation while requesting another model on that node or another occupied node. The kit does not define resource release, nested-call accounting, or deadlock prevention. **Adopt:** “Helper inference is a separately reserved registered job. A parent waiting for a helper holds no exclusive inference slot. All helper calls count toward the same fleet budget, and reservation acquisition follows one coordinator-defined order.”
17. **High · D — LIFE.md §2; perpetual policies.** “A perpetual lane never ends” conflicts with finite wall budgets and saturation stops. The kit has no explicit wake path after a saturated learning or digest lane receives new input. **Adopt:** “Perpetual describes recurring eligibility, not an immortal process. A lane may be WAITING_INPUT, SATURATED, STUCK, or terminal. New input creates a code-authorized next generation only for resumable nonterminal states. Cancelled or operator-stopped runs require explicit operator reauthorization.”
18. **High · D — BRIEF.md’s novel-work continuation requirement; policies/*.json.** Finite attempt, wall, and agent budgets can terminate work that is still producing valid novelty, while the brief requires continued attempts or useful subdivision without a task-lifetime time cap. **Adopt:** “Resource leases bound each execution quantum, not the cumulative lifetime of an authorized task. Valid novel progress can authorize another checkpointed quantum under the same task identity. Safety holds interrupt execution without declaring the task complete or discarding remaining work.”
19. **High · U — LIFE.md §4, §9, and §11; README recovery instructions.** “Stay,” “retired,” “stuck,” “resume,” “rest,” “cancel,” and “nothing restarts itself” do not form a state machine. **Adopt:** “Publish the complete transition table, actor authorized for each transition, and required evidence. Normal next-generation scheduling is distinct from process restart. CANCELLED, RETIRED, and operator STOPPED states have no autonomous outgoing execution transition.”
20. **High · U — LIFE.md §1, §4, and §7, progress counters.** “New items,” “progress,” “complete,” “stale,” and “novelty” lack code-defined predicates. New UUIDs or rewritten claims could appear productive indefinitely. **Adopt:** “Each task contract specifies its completion predicate and admissible novelty keys. Counters are derived from newly committed, independently validated outcomes, never model-reported counts, timestamps, or arbitrary identifiers. Infrastructure failures, empty input, and safety holds do not increment task-failure counters.”
21. **High · U — LIFE.md §9, recovery after host failure.** The timer can reappear after boot, but the kit does not define whether old reservations, queued births, or running worker node jobs remain valid. **Adopt:** “Every coordinator boot creates a new boot epoch and starts admission disarmed. It reconciles all nonterminal reservations with the hub before admitting work. Old-epoch jobs cannot commit results or create descendants until reconciled. Reboot does not clear STOP or resume cancelled/stuck runs.”
22. **Medium · U — LIFE.md §3, local task engine.** “Short discrete helper turns” does not define the exact input-size limit, token accounting, truncation policy, or fallback after refusal. **Adopt:** “The adapter checks the pinned local-engine limit before launch. Oversized inputs are partitioned at declared record boundaries into independently identified tasks; they are never silently truncated. Refusal returns INPUT_TOO_LARGE and does not trigger an unapproved cloud fallback.”

## Workspace, trust, and shared state

23. **High · D — bin/life-spawn-tick.py, QUEUE, APPROVED, REJECTED, HASHES; spawn/PROTOCOL.md.** Runtime spawn state is placed under the live repository’s KIT/spawn, outside the organism workspace. The claimed spawn/../STOP location consequently does not resolve to the stated workspace STOP path. **Adopt:** “All mutable spawn state lives under ROOT/var/spawn/; the sole stop authority is ROOT/control/STOP. KIT is read-only program material. Documentation must name these absolute logical locations consistently.”
24. **High · D — LIFE_ROOT handling across seed, validator, checks, and statements.** Setting LIFE_ROOT changes some Python paths but not hard-coded statement paths, validator roots, the kill-switch default, or workspace life. The kit can create one workspace and operate on another. **Adopt:** “LIFE v1 supports only the canonical ROOT and REPO named in the compatibility manifest. A conflicting environment override is a startup error.” Alternatively, implement one complete path-rendering layer; partial relocation is forbidden.
25. **High · U — bin/life-spawn-tick.py, imports and gate execution.** The coordinator imports symblic_autogen from an editable repository and executes checks from the kit. No ownership or integrity rule prevents an agent from changing its own admission machinery. **Adopt:** “Coordinator executables, imports, policy manifests, and acceptance checkers are outside worker-writable mounts and verified against the approved release manifest before use. Integrity failure disables admission. A worker-created replacement checker is never trusted merely because its path matches.”
26. **High · U — LIFE.md safety claims; all executable agent tasks.** Absolute-folder mentions and lint do not constrain the effects of generated shell commands. A task can name ROOT while writing elsewhere or controlling unrelated processes. **Adopt:** “Every worker receives an enforced filesystem/process sandbox: read-only declared inputs, one writable task directory, no control-plane credentials, no arbitrary host process control, and no access to the live checkout. Unsupported sandbox capability blocks launch.”
27. **High · U — README safety summary; command, source, log, and rejection artifacts.** “No credentials or private-store values” has no enforceable input or output boundary. Commands, tracebacks, CLI stdout, fetched pages, and model summaries could copy secrets into prompts, JSONL files, RUN.txt, or git. **Adopt:** “Private stores are absent from worker mounts and dependency bundles. Only allow-listed public/sanitized artifacts enter prompts. A trusted output filter runs before persistence, display, or promotion; an uncertain secret match quarantines the artifact rather than printing its contents.”
28. **High · U — LIFE.md §3, research networking; README guest-internet claim.** The text does not enforce that research uses only the approved broker, or prevent redirects and fetched URLs from reaching loopback, private services, or non-HTTP schemes. **Adopt:** “Model processes have no direct egress. Public-source retrieval uses the existing authorized broker, which validates scheme, destination, redirect chain, and resolved addresses. Guest requests cannot acquire the broker capability. No LIFE operation changes guest internet settings or creates a tunnel.”
29. **High · U — README safety summary; heartbeat and research outputs.** LIFE may eventually display source text, model output, patches, and status strings in the dashboard, but no rendering contract preserves the platform’s service-worker/CSP invariants or prevents treating those strings as active content. **Adopt:** “All LIFE-generated strings are rendered as escaped data. Generated HTML/JS is never activated by ingestion. Any dashboard integration must pass the existing CSP/service-worker regression suite and the applicable operator approval gate.”
30. **High · U — LIFE.md §2, shared git-backed workspace.** Multiple lanes and descendants can append to the same logical files or modify the same checkout without a writer, lock, merge, or conflict policy. **Adopt:** “Workers write immutable result bundles in separate task directories. A single code-owned committer validates and incorporates each bundle transactionally. It rejects stale input versions and overlapping writes; agents never resolve another task’s conflict by overwriting shared files.”
31. **High · D — organ verify instructions; seed/spawn --cwd ROOT; life-status.py.** Workers are told to write relative verify.txt; submissions use ROOT as cwd; status reads ROOT/organ-<name>/verify.txt. The packet does not establish either the per-organ files it promises or safe separation between runs. **Adopt:** “Each cell-generation has one isolated verification directory. Its absolute path is supplied in the task manifest and used by the statement, checker, and status collector. No shared root-level verify.txt is accepted.”
32. **High · U — LIFE.md §2–3 and §11, checkpoint artifacts.** The kit does not define where each run’s AUTOGEN-CHECKPOINT.json, HANDOFF.md, AUTOGEN-INDEX.jsonl, or AUTOGEN-SPLIT.txt lives, who writes it, or how it moves between worker node execution and home verification. **Adopt:** “These artifacts are run-scoped, versioned, and bound to a generation. Their exact schemas and limits are imported from the pinned platform contract. One trusted adapter owns publication and transfer; siblings cannot share a mutable checkpoint or split file.”
33. **Medium · U — LIFE.md §2, git-backed workspace.** No rule distinguishes versioned program material from runtime databases, WAL files, raw sources, logs, STOP state, or command text. **Adopt:** “Git tracks approved code, schemas, fixtures, and release manifests only. Runtime state, private/sanitized command envelopes, database sidecars, queues, and fetched content are explicitly excluded. Task commits are checked against that allow-list before devcheck and commit.”
34. **High · U — organs/*.lines.txt, JSONL outputs.** “Append one JSON line” does not define schema version, required fields, nullability, encoding, maximum record size, duplicate handling, or atomic publication. **Adopt:** “Every artifact type has a closed JSON schema. Files are UTF-8, one complete object per LF-terminated line, without duplicate keys. Workers do not append shared logs directly; the trusted committer appends validated records using stable event IDs. Readers ignore no malformed record silently.”
35. **High · U — spawn archives, source logs, metrics, and SQLite.** All major stores can grow indefinitely. There is no disk reserve, retention rule, compaction protocol, or behavior when storage fills. **Adopt:** “Initial v1 limits are 256 MiB of generated artifacts per cell, 10 GiB of total LIFE runtime state, and 1,024 pending spawn records. Admission holds before available disk drops below 2 GiB. Referenced evidence is never deleted automatically; quota exhaustion creates an operator-visible storage hold.” Archive/compaction must preserve durable dedup and retirement identities.
36. **Medium · U — schema.sql timestamps; logger, timer, and metabolism durations.** Database timestamps use integer Unix seconds, logger output uses unspecified local time, and continuous-load duration has no monotonic-clock or reboot treatment. **Adopt:** “Persist UTC Unix seconds for event timestamps and explicit monotonic-duration measurements tagged with boot epoch. Human-readable times include timezone. Wall-clock corrections cannot reduce accumulated load, extend a lease, or reorder events; event sequence numbers establish ordering.”

## Capacity, heat, stopping, and timers

37. **High · D — LIFE_MAX_RUNS; policies/*.json.** A count of live runs is not an agent, inference, memory, or process budget. The ten declared agents_max values sum to 144; that is not evidence of 144 concurrent agents, but it demonstrates that the run ceiling does not express the underlying work budget. **Adopt:** “Maintain separate limits for admitted workflows, active CLI agents, active inference jobs, benchmarks, and home verifiers. Every nested attempt obtains the relevant reservation before launch.”
38. **High · D — life-seed.sh; LIFE.md §11; spawn gate scope.** Seeds bypass STOP, heat, and live-run admission. Subsequent generations, regeneration, decomposition, designer activity, and self-split expansion also are not guarded by this tick. **Adopt:** “All LIFE execution starts, including seeds and internal expansion, pass through a shared admission hook in the actual launcher. No direct seed start calls remain. Where the existing platform cannot supply that hook, LIFE remains disabled rather than claiming global control.”
39. **High · U — LIFE.md §2, capacity descriptions.** Approximate machine memory and a historical “free” reading cannot determine present admission. No reservation includes model weights, context memory, CLI processes, other users’ jobs, or system reserve. **Adopt:** “Admission requires fresh per-node capacity telemetry and a declared worst-case job reservation. Reserve at least 2 GiB for the node outside LIFE, respect its existing Ollama cap, and subtract outstanding reservations before allocating. Missing telemetry or an unmeasured model reservation means HOLD.”
40. **High · D — LIFE.md §6 versus organ placement.** The claim of “one perpetual model lane per worker node” conflicts with four perpetual organs assigned to node-i and two assigned to node-f. Even if inference is serialized, CLI loops and benchmarks remain separate resource consumers. **Adopt:** “Replace the claim with the actual placement table and enforced concurrency limits. A node receives no second exclusive computation lease while its first is held; queueing is explicit and visible.”
41. **Medium · U — LIFE.md §2, sleeping nodes.** “Shows as INFRASTRUCTURE and the lane waits” does not specify detection, retry cadence, reservation release, timeout classification, or handling of work that may still be running. **Adopt:** “Node disappearance changes affected leases to UNKNOWN, blocks replacement execution, and triggers hub reconciliation. Readiness retries occur every 300 seconds without consuming task-novelty budget. A replacement attempt starts only after the prior attempt is confirmed stopped or fenced.”
42. **High · U — LIFE.md §6, resource coverage.** One-model-per-node does not bound compilers, test processes, child shells, benchmarks, resident models, temporary files, or host-side verification. **Adopt:** “Each job declares CPU, memory, process-count, temporary-storage, and elapsed-time limits enforced by the registered launcher. Limits include descendants. Home verification has its own bounded queue and reservation; it cannot contend without limit with the dashboard or browser daemon.”
43. **High · U — LIFE.md §3, cloud CLIs.** “Cheapest” and “last resort” do not define permission, token/call limits, billing exposure, or provider escalation. All ten default autogen lanes can create cloud-agent activity. **Adopt:** “A cloud tool loop requires an operator-issued authorization bound to task ID, provider, allowed engine, expiry, and call budget. No automatic provider change is allowed outside that authorization. Missing usage accounting disables automatic escalation.”
44. **High · D — checks/heat-gate.sh.** The host’s load average and IO pressure do not measure worker node temperatures or worker node continuous load. A cool idle coordinator can admit work onto an overheated worker node. **Adopt:** “Keep host-pressure checks as coordinator protection only. Fleet admission additionally requires fresh, code-validated per-node thermal, capacity, and lease telemetry for every target node. Host ALLOW is never sufficient for worker node admission.”
45. **High · D — LIFE.md §6; perpetual policies.** Twelve- and twenty-four-hour wall budgets, hour-long attempts, and independently staggered intervals do not enforce a shared rest period before one hour of sustained fleet work. **Adopt:** “Replace the claimed interval-based heat guarantee with an actual fleet duty-cycle governor. It prevents starting any job whose maximum remaining lease would cross the work-window boundary and suspends or terminates LIFE-owned computation at lease expiry.”
46. **High · U — LIFE.md §6, “continuous all-worker node load” and “rest.”** Neither the beginning nor end of a load period is defined. Short gaps, staggered nodes, model residency, or ongoing benchmarks could reset a naïve counter. **Adopt:** “A v1 fleet work epoch permits at most 3,000 seconds of computational leases, followed by at least 600 consecutive seconds with no LIFE model, CLI-compute, or benchmark work. Shorter gaps do not reset the epoch. Node-specific thermal limits must be populated in the approved hardware manifest; absent limits mean HOLD.”
47. **High · D — organs/metabolism.lines.txt; bin/life-spawn-tick.py.** Metabolism writes a fan-out decision, but the spawner never reads it. The supposed governor is advisory output from an agent. **Adopt:** “One deterministic governor owns admission state. Both scheduling and status read its signed/versioned snapshot. The metabolism log records that decision; it does not independently invent it. Admission rejects missing, stale, malformed, or mismatched governor snapshots.”
48. **High · U — LIFE.md §6, dashboard API reads.** /api/cluster/status, /capacity, and /highpower/state lack an exact verified route contract, response schemas, field units, authentication method, request deadlines, and freshness requirements. **Adopt:** “A pinned API adapter identifies each full route, allowed host, method, required JSON fields, types, units, and error mapping. It uses existing authorized loopback access on the host only. Telemetry older than 15 seconds is inadmissible; missing or unexpected fields produce HOLD.”
49. **High · D — checks/heat-gate.sh, IO parsing.** A failed or empty IO-pressure read becomes zero; nonnumeric text is coerced numerically. Thus missing telemetry can become ALLOW. **Adopt:** “Both readings must parse as exactly one finite nonnegative numeric value from the expected field. Missing files, command errors, duplicate matches, or malformed values print HOLD reason=TELEMETRY_INVALID and exit 4. Never substitute zero for a failed read.”
50. **High · D — bin/life-spawn-tick.py, main().** STOP and heat are checked once before the queue loop. A STOP created or heat condition changed during processing does not prevent later births in that same tick. **Adopt:** “Revalidate the admission epoch and fresh governor decision immediately before each reservation and submission. The launcher itself verifies the same epoch at actual execution start. Revocation invalidates all not-yet-started reservations.”
51. **High · D — README kill switch; checks/kill-switch.sh.** STOP only prevents this spawner from submitting new runs. Existing perpetual runs may finish, wait their normal interval, and continue; internal regeneration and splits are not stopped. “Finish and rest” is therefore not a durable freeze. **Adopt:** “STOP revokes authorization for all new LIFE execution quanta, including generations, retries, helpers, seeds, and descendants. Existing work checkpoints or ends within its lease. It remains paused until explicit rearming.”
52. **High · U — STOP file creation and probing.** Ownership, permissions, symlink behavior, removal authority, and what “instantly” means are undefined. A worker with ROOT write access could remove STOP; existence probes do not establish a linearizable stop event. **Adopt:** “Only the operator/control service can mutate the stop state. A stop operation atomically increments the admission epoch and returns an acknowledgement after revocation is durable. Any stop-path integrity error is treated as stopped. Workers cannot alter that directory.”
53. **High · U — README “Stop everything.”** The awk loop races with births, parses presentation text, and does not define descendant cancellation, checkpoint durability, or confirmation that processes actually stopped. **Adopt:** “First revoke admission. Obtain exact LIFE run and job IDs from the typed registry; request cancellation through the existing hub; wait for every LIFE-owned descendant to become terminal or fenced. Report unresolved jobs explicitly. Never cancel slices, unrelated processes, or the busy browser daemon.”
54. **High · U — bin/life-spawn-tick.py, environment configuration.** Negative, zero, malformed, or excessive limits are not validated. Arbitrary REPO, ROOT, and DASH_URL values can redirect trust or operational scope. **Adopt:** “Load a closed, operator-approved configuration schema before importing platform code. Every integer rejects booleans and strings; limits must be positive and within the release’s supported hard bounds. URLs must match the approved the host loopback endpoint. Invalid configuration exits without reading the queue or spawning.”
55. **High · U — LIFE.md §6 and §11 gap 5.** A failed coordinator or hung agent can outlive the intended rest period. No independent worker-side lease expiry enforces the stop. **Adopt:** “Registered worker jobs have launcher-enforced leases renewed only by the current coordinator epoch. Lease expiry stops LIFE-owned computation and prevents result commitment. Missing renewal never grants more runtime. Implement this through the existing hub, not SSH watchdog shortcuts.”
56. **Medium · U — LIFE.md §9, timer cadence.** “Every five minutes” does not specify whether the interval is measured from start or completion, how long a tick may run, or how delayed ticks behave. **Adopt:** “First tick occurs 300 seconds after timer activation; subsequent ticks occur 300 seconds after the previous tick finishes. A tick has a 30-second overall budget and processes at most 16 records. Missed ticks do not accumulate catch-up executions.” Encode those semantics explicitly in the unit and coordinator.
57. **Medium · U — LIFE.md §9, unit installation.** Working directory, Python environment, configuration source, unit ownership, resource restrictions, and installation verification are omitted. **Adopt:** “Ship exact service/timer files in the release manifest, with absolute executable and working-directory paths, an operator-controlled configuration file, restricted writable paths, and bounded service resources. Installation validates ownership and hashes, reloads the user manager, and verifies the installed unit definitions before enabling admission.”
58. **Medium · U — LIFE.md §9; spawn-tick exit values.** STOP and heat return 3 and 4, but the service does not classify these expected holds or explicitly state restart behavior. **Adopt:** “The service uses Restart=no; exits 3 and 4 are expected non-birth outcomes, not restart triggers. Exit 0 means the tick completed, not that every queued record was admitted. Configuration, registry, and integrity failures have documented distinct nonzero outcomes and produce an alert.”
59. **Medium · U — LIFE.md organ intervals and global budget.** A prolific lineage can occupy every workflow slot or worker node queue, starving operator commands, immunity, and useful unrelated work. **Adopt:** “Operator command ingestion and safety control remain deterministic and independent of model slots. The scheduler reserves explicit service capacity for command classification and required verification, limits each lineage’s share, and applies a documented fair queue. Urgency never overrides STOP, thermal, memory, or authorization gates.”

## Spawn admission, lineage, and durable submission

60. **Medium · D — spawn/PROTOCOL.md, <name>; spawn-tick queue loop.** The documented slug regex is never checked. Invalid names enter logging and archive naming. **Adopt:** “Before opening a record, require its basename to match ^[a-z0-9][a-z0-9_-]{0,63}$ exactly. Invalid entries are recorded by escaped identifier and moved through a safe code-owned quarantine path, without interpreting their contents.”
61. **High · D — spawn/PROTOCOL.md, exact layout; spawn-tick record parsing.** reason.txt is not required, extra files are accepted, and most “exact keys” are neither required nor validated. **Adopt:** “Admission uses a closed record schema specifying required files, permitted optional files, exact JSON properties, types, bounds, and version. Unknown properties or extra executable content are rejected. Human-readable reason text is required but never treated as authorization.”
62. **High · D — spawn-tick filesystem checks and reject().** isdir() and isfile() follow symlinks. A queued symlink can cause reads or REJECT.txt writes outside the queue; linked files can substitute protected content. **Adopt:** “Open records relative to a trusted directory descriptor without following symlinks. Accept only ordinary directories and regular, single-link files owned by the expected producer principal. Rejection metadata is written outside the untrusted record, in coordinator-owned storage.”
63. **High · U — spawn record loading.** Files are read fully before independent byte-size bounds; record counts and directory entries are unbounded. **Adopt:** “Before parsing, limit statements to 64 nonblank lines, 60,000 characters, and 240,000 UTF-8 bytes; policy to 64 KiB; lineage and reason to 4 KiB each. Reject oversized files without loading them. Queue-entry count and total queue bytes are included in storage admission.”
64. **High · D — spawn-tick incomplete-record rejection.** A producer writing files directly under queue/ can be observed between writes and permanently rejected. **Adopt:** “Producers write into a private staging directory. The trusted publisher validates completeness, synchronizes the files and directory, then atomically publishes the complete directory into the queue. The consumer never scans producer staging directories.”
65. **High · D — spawn-tick main().** There is no lock or atomic claim. A timer invocation and manual invocation can both validate and submit the same record. **Adopt:** “Each tick acquires an exclusive coordinator lock, and each record transitions atomically from QUEUED to CLAIMED using its immutable record ID. Failure to acquire the lock exits without processing. Claims are recoverable through the durable state machine, not by deleting lock files blindly.”
66. **High · D — live_run_count() followed by start.** A count check does not reserve capacity. Multiple submissions can pass before the hub exposes them as live, even within one tick. **Adopt:** “Admission atomically reserves a workflow slot before submission. Reserved, submitted-but-unconfirmed, and reconciliation-pending jobs count against the ceiling. A reservation is released only after confirmed non-start or terminal completion.”
67. **High · D — live_run_count(), subprocess return handling.** A nonzero autogen list exit is ignored. Empty stdout after an authentication or server error becomes a count of zero, despite the fail-closed comment. **Adopt:** “Require successful command completion and a valid typed response before calculating capacity. Any nonzero exit, malformed response, or incomplete listing returns CAPACITY_UNKNOWN and prevents admission.”
68. **High · D — live_run_count(), substring parsing.** Searching for 'active' also matches 'inactive'; searching any line for 'life-' is not run-identity validation. Other live states may be missed. **Adopt:** “Use a version-pinned machine-readable adapter with exact run IDs and enumerated states. Define explicitly which states consume workflow and execution reservations. Do not infer status from presentation text or introduce an unverified CLI flag.”
