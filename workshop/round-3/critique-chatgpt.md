## Execution, shutdown, and submission safety

1. **[high] spawn/PROTOCOL.md §2: agent-cell division is unreachable.** The commit phase requires 3,600 seconds of remaining hard budget, but an entire tick has only 2,700 seconds. Every agent division must wait until it expires. **Replace with:** “Each complete child-workspace build has a 600-second deadline. Reserve 2 × (600 + KILL_GRACE) + 60 = 1320 seconds for both builds, cleanup, and publication. Begin only before TICK_DEADLINE with at least 1,320 hard-budget seconds remaining.”
2. **[high] bin/life_common.py, Procs.end: terminating the leader does not terminate its surviving children.** SIGKILL is sent only when proc.poll() is None. A leader can exit on SIGTERM while a child ignores it; that group never receives SIGKILL. **Replace with:** “After the grace deadline, terminate every remaining process in the recorded execution group, regardless of the leader’s exit status. Completion requires the execution group to be empty, not merely its original PID to have exited.”
3. **[high] bin/life-check.py, sandboxed: the sandboxed command escapes the parent’s process group.** start_new_session=True creates another session, but the wrapper neither registers that group with LIFE nor forwards SIGTERM. Its timeout uses subprocess.run, whose timeout handling kills the direct child, not an arbitrary descendant tree. **Replace with:** “Use the shared supervised runner. Register the sandbox execution before waiting; forward cancellation; terminate and reap its entire execution group before deleting HOME or returning.”  [Python documentation](https://docs.python.org/3/library/subprocess.html?utm_source=chatgpt.com)
4. **[high] bin/life_common.py, scope_argv: transient scopes have no independent lifetime bound.** These scopes are outside the tick’s service cgroup, have no recorded unit name, and omit RuntimeMaxSec and TasksMax. A surviving descendant can outlive the tick and retain its resources. **Replace with:** “Name every scope life-<call_id>.scope; persist its identity before launch; set RuntimeMaxSec to the action’s deadline and TasksMax=64; explicitly stop and confirm the scope empty on cancellation and recovery.”  [Ubuntu Manpages](https://manpages.ubuntu.com/manpages/noble/man5/systemd.scope.5.html)
5. **[medium] bin/life_common.py, Procs.run: stdin can block before supervision starts.** The blocking proc.stdin.write() occurs before registration in self.live and before the timeout deadline is established. A child that does not consume sufficiently large input can become invisible to STOP. **Replace with:** “Register the process and establish its monotonic deadline immediately after creation. Feed stdin nonblockingly under that same deadline; cancellation closes stdin and terminates the execution group.”
6. **[high] bin/life_common.py, Procs.run: a fast successful process can bypass the output cap.** The size check is reached only after wait(timeout=1) times out. A process that exceeds the cap and exits before that timeout is accepted. A scaled-limit probe accepted 16 KiB with an 8 KiB limit. **Replace with:** “Enforce aggregate output limits while reading, and check the final captured size before accepting any return code. An output-limit violation always returns a distinct non-success outcome.”
7. **[high] bin/life_common.py, http_json: its timeout does not implement LIFE’s request deadline.** The function explicitly uses per-socket-operation timeouts. A response that continuously trickles bytes can exceed the promised 30- or 60-second total bound and consume the tick. **Replace with:** “One monotonic deadline covers connection, headers, body, and decoding. At expiry, close the connection and raise Telemetry. A separately supervised helper must enforce the deadline when the HTTP library cannot interrupt the whole operation.”

## Reproduction, scheduling, metabolism, and model control

60. **[high, U] backlog_ticks: interrupted consecutivity is undefined.** Lifecycle evaluation occurs only after the observe/hold exit. Two qualifying ticks, a long freeze, and another qualifying tick can preserve a stale count unless interruption behavior is specified. **Replace with:** “backlog_ticks increments only when the current tick is armed, unfrozen, unheld, and the cell meets the workable-backlog threshold. Every intervening tick failing any condition resets it to zero, including observe-only ticks.”
61. **[medium] LIFE.md §4: holds prevent the promised division expiry.** Expiry is performed in lifecycle after the hold exit, so an armed but held system can leave divisions open beyond 10,800 seconds. **Replace with:** “Expired-division abortion is reconciliation, not new work. Run it before the observe/hold exit whenever the registry is usable. It cancels outstanding division calls, records abortion, and restores the parent without launching new work.”
62. **[high, U] spawn/PROTOCOL.md §2: filesystem preparation lacks crash states.** A crash after publishing one child workspace but before the registry transaction leaves paths whose ownership and reuse are undefined. **Add:** “A division records both child IDs, target paths, expected repository identities, and preparation states before creating files. Workspace publication is idempotent only when its manifest matches that intent. Recovery either completes the same division or removes only its verified orphan preparations before recording abortion.”
63. **[medium, U] Division records do not pin their release and decision provenance.** A release can change between the multi-tick foci and assignment stages, but divisions records no release or input digests. **Add:** “At division start, record the release ID, parent focus, queue snapshot digest, program digests, and parent rung state. 69. **[medium, U] Offline migration: absence of samples is not distinguished from continuous offline evidence.** “Offline in every sample of the last six hours” can be vacuously true or based on a few sparse samples. **Add:** “Persist offline_since only after an explicit valid offline observation. Move only after six hours of adequately sampled explicit offline observations, with no unresolved execution on the old node.”
70. **[medium, U] Node-slot scheduling has no total order across cells.** Several seed cells share nodes, but the packet does not specify which eligible cell receives the node’s single action. **Add:** “Build one eligible action per cell. Sort candidates by last_served_at ascending, priority descending, cell_id ascending, then action ID ascending. Select the first admissible candidate for each node and update last_served_at at reservation. Skip blocked candidates rather than blocking the entire node queue.”
71. **[high] LIFE.md §10: the duty-cycle promise is not enforced by admission thresholds alone.** A 1,500-second research run can start just before a node reaches 3,000 busy seconds; a 3,600-second agent run is longer than that entire allowance. **Replace with:** “Reserve each action’s worst-case remaining runtime against node and fleet work allowance before admission. Execution must be cancellable at the lease deadline. Until the platform can enforce that lease for agent attempts, LIFE must not admit an agent run that can exceed the remaining allowance.”
72. **[high, U] Governor accounting: unavailable telemetry can be mistaken for quiet.** The hold rule says counters continue, but the packet does not define whether missing CPU samples or failed fleet reads add quiet seconds and reset the work window. **Add:** “An interval with insufficient valid telemetry is unknown, not quiet. Unknown intervals never increase quiet_seconds, clear rest, or reset accumulated work. Recorded LIFE execution intervals still contribute busy time. Recovery requires the stated consecutive duration of positively observed quiet.”
73. **[high] LIFE.md §10: the slot refresh does not refresh all admission constraints.** It removes nodes based on status but does not explicitly recheck high-power mode, the host pressure, or all rest/hold conditions after earlier long stages. **Replace with:** “Before every launch batch, refresh the complete governor input set when any admission input is older than 120 seconds. Recompute global holds and node eligibility from that snapshot. A status-only refresh cannot authorize work against an older high-power mode or host-pressure result.”
74. **[medium, U] Telemetry validation leaves scalar domains incomplete.** Temperature range, memory representation, restUntil units, booleans masquerading as numbers, and missing CPU-count behavior are not fully specified. **Add:** “Reject booleans as numeric values. CPU is finite 0–100; temperature is finite −50–150 °C; available memory is a nonnegative integer byte count bounded by reported total memory; restUntil is integer Unix seconds. Missing total memory, invalid pressure, or unknown CPU count prevents the affected admission.”
75. **[high, U] busy() intervals do not define uncertain and never-submitted work precisely.** A not_submitted row, an unresolved intent, or a terminal record without ended_at can either overcount indefinitely or undercount a real execution. **Add:** “Every execution record distinguishes reservation time from confirmed execution time. Confirmed non-admission contributes zero execution time. Unresolved admission conservatively retains a reservation until resolved. Terminal records require an end timestamp. The governor publishes separately measured busy time and conservative uncertainty reservations.”
76. **[medium, U] Duration accounting lacks a complete clock-discontinuity rule.** Clamping one sample delta does not define agent age, offline age, cooldowns, quarantine age, or cross-boot intervals. **Add:** “Use monotonic time for all within-boot durations and deadlines, storing the boot ID with persisted monotonic intervals. Use UTC only for calendar budgets and display. After reboot or an unreconstructable clock discontinuity, require fresh evidence for quiet/offline durations and reconcile executions before releasing reservations.”
77. **[medium, U] Canary scheduling can starve the only recovery path.** A due round is skipped unless 600 deadline seconds remain, but polling and other maintenance precede it. Repeated slow maintenance can leave the canary hold uncleared forever. **Add:** “Reserve the canary round’s 600 seconds before non-emergency maintenance. After STOP and essential execution reconciliation, a never-passed or failed canary round has priority over ordinary polling, reports, and backups. A failed round is retried on the next tick with that reservation.”
78. **[medium] LIFE.md §8: rung demotion has no evidence that the cheaper model works.** Ten successes at a higher base rung trigger a move down, even when the lower rung consistently failed. This creates predictable up/down oscillation. **Replace with:** “Successes at the current rung do not justify demotion. Demote only after ten explicitly budgeted lower-rung probes succeed on representative inputs. Record probe outcomes separately from production outcomes and reset the probe window after any lower-rung failure.”
79. **[medium, U] Escalation does not define the effective rung after missing-model skipping.** A nominal base rung can resolve to a higher installed model. Incrementing rung_extra from the nominal rung can select the same failed model again. **Add:** “Persist the effective rung actually attempted. Semantic escalation starts strictly above that rung, skipping unavailable models. Each installed rung is attempted at most once per item stage, except the program’s own bounded internal retries.”
80. **[high, U] Infrastructure classification relies on an unspecified text pattern.** The packet gives examples and an ellipsis, not the exact regex, precedence, normalization, or handling of mixed failures. **Add:** “Publish the complete structured error-kind mapping and any fallback regex as a code-owned constant. Structured kinds take precedence. A mixed set containing any semantic failure is semantic. Unknown kinds are protocol failures; untrusted output text cannot override a structured semantic failure.”
81. **[high, U] The model-call daily budget lacks reservation semantics.** It is unclear whether LIFE charges actual calls, worst-case calls, failed calls, or calls whose traces are unavailable after a crash. **Add:** “Before each genome run, reserve 12 model-call units and one program-run unit atomically against the captured UTC day. Reservations are never refunded. Store actual calls separately for metrics. Every retry is a new reservation; a missing trace cannot reduce the reserved charge.”
82. **[high, U] Research has a tool-use cap, not an enforced generation cap.** RESEARCH_TOOLS=4 does not itself prove how many model launches the wrapped implementation may perform. tracked_launch does not enforce a count. **Add:** “Set RESEARCH_MAX_MODEL_CALLS=5, reserve five call units before a research run, and enforce the limit in tracked_launch before each submission. Exceeding it terminates the run with model_call_limit; no additional finalization generation is exempt.”
83. **[medium, U] Model memory assumptions are not bound to model identity or context settings.** The table identifies mutable tags, while OLLAMA_LIMITS omits a context-size limit. Daily installation checks do not attest that weights or runtime settings still match the memory allowance. **Add:** “Record the resolved model digest, quantization metadata, and explicit context limit for every admitted model. Revalidate these before launch. Memory admission uses a measured peak bound for that digest and configuration; a mismatch holds the model pending operator-approved recalibration.”
84. **[low] LIFE.md §8: not every answer is limited to 40 words.** The quote ask is unrestricted Text with a 400-character cap and can exceed 40 words. Therefore the stated reason that 320 tokens always suffice is false. **Replace with:** “Generation limits are hard execution limits, not a guarantee that every valid textual answer fits. The quote field is bounded by 400 characters. Truncation or an incomplete typed result is a semantic failure and follows bounded retry rules.”

## Registry and migration integrity

85. **[medium] db/life.sql: text primary keys permit NULL identities.** The supplied schema accepted a cell with cell_id=NULL; its checks also passed PRAGMA integrity_check and foreign_key_check. **Replace with:** “Every non-integer primary key is explicitly NOT NULL. Apply the same rule to all identifiers in both databases. Add negative tests inserting NULL into every identity column and require rejection before the schema is admitted.”
86. **[medium] db/life.sql: declared integer columns do not guarantee integral values.** A cell with depth 1.5 and ID learning.1.5.00000001 was accepted. Several counters likewise have only range checks. **Replace with:** “Use strict tables where supported and explicit integer-type checks for depths, counters, priorities, timestamps, and budgets. Canonical identity reconstruction must use an integer depth from 0 through 10. Add fractional-value negative tests for every integral field.”
87. **[medium] db/life.sql, items: stage and ownership relationships are not constrained.** The schema accepted a digest/source item at apply, assigned to a learning cell, while both registry canaries passed. **Add:** “Enforce the complete organ/kind/stage matrix. A non-null assigned cell must have the same organ as its item. Running items require an appropriate execution or local-stage reservation. Validate these relationships on insertion, assignment, stage transition, and recovery.”
88. **[medium] db/life.sql, cells: lineage constraints permit wrong parents.** A digest child at depth 9 can reference a learning seed at depth 0. **Add:** “A non-seed child has the same organ and kind as its parent and depth exactly parent.depth + 1. Seeds alone have no parent and depth 0. Enforce these relationships with insert-time constraints or triggers and prohibit later modification of birth facts.”
89. **[high, U] LIFE.md §6: the payload table is not a closed schema.** Types, nullable fields, optionality, enum values, and lifecycle timing are missing. Fields needed before submission, including migration and draft metadata, appear only under later stages. **Add:** “Include a versioned schema for each (organ, kind, stage), specifying exact required and optional keys, scalar types, ranges, and references. Prelaunch metadata must be valid in the prelaunch stage. Validate before committing every transition, not only before rendering.”
90. **[medium, U] meta and auxiliary JSON fields lack schemas.** meta.models, fault state, watch scheduling data, division assignments, manifests, and other JSON columns have no complete field/type/version contracts. **Add:** “Define a registry of allowed meta keys and closed schemas for every JSON-bearing column. Unknown keys or schema versions cause an integrity hold. Runtime code may not invent undocumented meta structures or treat malformed values as empty defaults.”
91. **[medium, U] Audit relationships and immutability are largely conventional.** Calls, results, proposals, migrations, and releases contain identifiers without consistent foreign keys, while append-only and immutable descriptions are not enforced. **Add:** “Specify and enforce each authoritative relationship, including execution-to-item, execution-to-release, proposal-to-base-release, and result-to-execution. Birth facts, execution inputs, accepted artifact digests, and lifecycle events are immutable after insertion. Corrections append a superseding record rather than rewriting evidence.”
92. **[medium, U] Truncated IDs lack collision verification.** Existing IDs are treated as duplicate identities, but most records do not retain the complete canonical identity and full digest needed to distinguish a collision. **Add:** “Store the complete canonical identity and full SHA-256 for every shortened ID. On an ID conflict, compare both before deduplicating. A differing identity is identity_collision, causes no overwrite or merge, and goes to the operator. Short IDs remain display aliases only.”
93. **[high] snapshot_problems: an accepted migration can poison every later snapshot.** The validator explicitly accepts a column named view, but the next schema snapshot rejects the word VIEW anywhere, including identifiers and literals. This was reproduced. **Replace with:** “Validate snapshot statement structure using the same token-aware grammar as migrations. Forbidden statement kinds are not forbidden words inside identifiers or string literals. Every accepted migration must produce a snapshot that the snapshot validator accepts.”
94. **[high] Migration validation: AUTOINCREMENT creates an unreplayable internal-table snapshot.** An accepted table with INTEGER PRIMARY KEY AUTOINCREMENT creates sqlite_sequence; replaying its captured CREATE statement fails because the name is reserved. This was reproduced. **Replace with:** “Exclude SQLite-generated internal objects from replay snapshots and recreate them only through their owning user-table DDL. Validate snapshot round-tripping after every proposed migration. Alternatively, explicitly refuse AUTOINCREMENT until internal-object handling is implemented.”
95. **[high] LIFE.md §7.8: snapshot ordering creates indexes before their tables.** Ordering by type, name places index before table. The supplied replay loop executes in that order and fails after an indexed schema exists. This was reproduced. **Replace with:** “Serialize user tables first, ordered by name, then user indexes, ordered by name. Omit objects with no SQL definition and SQLite-generated internal objects. Replaying the produced snapshot must succeed before it is published.”
96. **[high] REFERENCES_RX: quoted references bypass the org_ restriction.** REFERENCES [schema_migrations](migration_id), backtick quoting, and single-quoted identifiers passed the validator. **Replace with:** “Identify REFERENCES clauses through tokenization outside literals and comments. Resolve or explicitly reject every supported identifier-quoting form. Every referenced table must be an unqualified canonical org_ name. No accepted syntax may evade reference inspection.”
97. **[medium] organs/database.lines.txt: its instruction contradicts ADD COLUMN.** It says every table and index name must not exist in the snapshot, although ALTER TABLE necessarily targets an existing table. **Replace with:** “Every newly created table or index name must be absent from the snapshot. An ALTER TABLE target must already exist and begin with org_; only the added column must be new. CREATE INDEX targets must exist in the snapshot or be created earlier in this migration.”
98. **[high, U] Migration numbering is not explicitly reserved throughout the draft.** The number must be known before rendering, but the draft payload schema does not require it and retry reuse is unspecified. **Add:** “Allocate and persist the migration ID before the first draft attempt. It remains unchanged through all retries for that request. Maintain a durable monotonic high-water mark that includes pending, refused, and applied migrations and the organism ledger. Allocation is never inferred solely from terminal registry rows.”
99. **[high, U] Migration validation ignores existing row contents.** Replaying schema into an empty database cannot establish that a new unique index or added constraint is valid for operator-populated tables. The resulting live failure has no precise non-retry classification. **Add:** “Validate against a bounded backup containing current schema and data. Constraint violations are permanent refused outcomes, not infrastructure retries or tick faults. Before commit, recheck against the current database under the migration transaction and roll back on any mismatch.”
100. **[high, U] Migration processing has byte bounds but no total execution or growth bound.** Small DDL can require substantial scanning or index construction. The in-memory validator runs directly in Python, and the live apply stage has no named total DDL deadline. **Add:** “Set a 120-second validation deadline and a 120-second transactional DDL deadline, with cancellation-aware SQLite progress checks and supervised execution. Reserve predicted storage before index construction and cap resulting organism size. Timeout rolls back and records a bounded refusal.”
101. **[high, U] LIFE.md §7.8: migration evidence is recorded after the irreversible database commit.** SQL is saved to the bundle and registry only after the organism transaction. A crash can leave an applied ledger entry without the durable recovery material promised elsewhere. **Replace with:** “First publish and fsync immutable SQL, its digest, and a registry migration intent. Then back up and apply the organism transaction. Finally reconcile the registry and workspace. Recovery uses the durable intent and SQL; it never depends on an agent workspace surviving.”
102. **[high, U] Migration recovery ordering conflicts with the new-name rule.** The text first requires validation against the current schema, which rejects already-created names, then describes recovery of an already-applied migration. **Replace with:** “Check schema_migrations before additive-new-name validation. Same ID and same digest means reconcile as already applied without re-executing DDL. Same ID with another digest is an integrity failure. Only an absent ID enters new-migration validation.”
103. **[high, U] Registry and organism restore lack a reconciliation authority.** Restoring only one database can leave registry-applied migrations absent from the organism or organism-applied IDs unknown to the registry. **Add:** “Before database work resumes, compare the two ledgers against a verified recovery manifest. An organism-only applied record is imported into registry history from its matching intent. A registry-only applied record causes migration_recovery_required; replay requires verified SQL and explicit operator recovery. Number allocation includes both ledgers.”
104. **[high, U] Patch and proposal publication claims a transaction across files and SQLite.** Writing bundle files, inserting rows, queueing review, and resetting the clone cannot be one SQLite transaction. Crash ordering is missing. **Replace with:** “Write a bundle into an intent-owned temporary directory, fsync files and directory, and atomically publish it. Then insert its registry row and downstream item in one transaction. Only afterward release/reset the workspace. Recovery reconciles published unreferenced bundles and never fabricates missing bundle bytes.”

## Commands, research, provenance, and input handling

105. **[high] Permanent item deduplication prevents legitimate recurring work.** A recurring research command produces the same normalized question identity forever. Likewise, acknowledging a failed watched finding does not change its test/base/error identity, so new_item returns the ended item instead of creating the promised retry. **Replace with:** “Separate semantic identity from execution occurrence. Agenda periods and acknowledged finding retries receive new occurrence IDs while referencing the existing semantic question or finding fingerprint. Deduplication prevents duplicate concurrent occurrences, not all future work on the same subject.”
106. **[medium, U] Research source counting alternates between globally new and question-new sources.** Constants describe “zero new sources,” while the stage counts known sources for a question. Repeated results for the same question need an explicit rule. **Replace with:** “found equals the number of distinct source keys linked to this question. A run’s progress is the number of newly inserted question-source relationships, regardless of global source novelty. Zero such insertions increments dry_runs; any insertion resets it.”
107. **[medium] Known but failed sources can count as evidence indefinitely.** Globally known sources are never fetched again, including entries whose first fetch was empty, refused, or exhausted by transient failure. Later questions can count them without usable text. **Replace with:** “Source identity and usable snapshot status are separate. Only a valid fetched snapshot counts toward a question’s usable-source target. Failed fetches retain their history but have an explicit operator-retry path; transient-failure retry creates a new fetch attempt without duplicating source identity.”
108. **[medium] Long-URL fallback identity lowercases case-sensitive components.** Lowercasing the whole URL can merge distinct paths or query values. **Replace with:** “Normalize scheme and hostname case only; preserve path and query case unless equivalence is established by the relevant scheme. Remove fragments only under an explicit fetched-resource identity rule. Hash the canonical structured URL, and retain the original URL for provenance.”  [RFC Editor](https://www.rfc-editor.org/rfc/rfc3986)
109. **[medium, U] Shared results cannot be represented by one origin string.** A source can answer many questions, and a deduplicated item can be relevant to several commands, but item ancestry has one untyped origin. **Add:** “Use typed many-to-many provenance edges identifying parent kind, parent ID, child kind, child ID, and relation. Include command-to-question, question-to-source, source-to-fact, and fact-to-derived-item edges. Reports and completion queries follow this graph with cycle detection; deduplication must preserve every requesting command’s relationship.”
110. **[high, U] The 500-item report limit cannot define command completion.** A command with a 501st unfinished descendant can be incorrectly marked complete if traversal stops at the display cap. **Replace with:** “The 500-item limit applies only to one report page. Completion examines the full reachable provenance graph and cannot be inferred from a truncated traversal. Reports include continuation information and an explicit truncation marker. Cycles or traversal failures leave completion unresolved and open a notice.”
111. **[medium, U] Route-specific command length handling is incomplete.** Inbox text allows 4,000 bytes; requests and experiment seeds allow 600 characters; lessons allow 300. Only learning explicitly defines an overlength notice. **Add:** “Before routing creates an item, validate the full authoritative command against that route’s exact limits. Reject overlength or underlength commands to owner with the applicable limit. Never silently truncate the operative instruction or replace it with the classifier’s restatement.”
112. **[medium, U] Whitespace-only inbox commands have no defined refusal.** They satisfy the byte-length rule but become empty after stripping, violating the command table’s minimum length. **Add:** “After UTF-8 decoding, strip outer whitespace and require at least one non-whitespace character before any insert. Whitespace-only input is moved to refused storage with reason empty_command; it never raises a tick fault.”
113. **[high] Inbox opening can block before rejecting a FIFO.** O_NOFOLLOW does not make opening a FIFO nonblocking. Checking regular-file type afterward is too late. **Replace with:** “Open inbox entries with O_RDONLY | O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC, then validate the opened descriptor as an owned regular file before reading. Apply the same bounded regular-file reader to ARMED and all operator configuration files.”
114. **[high, U] Inbox acceptance lacks crash ordering across database and archive moves.** A crash between inserting the command, creating its item, and moving its file can duplicate work or leave accepted text unrepresented. **Add:** “Commit the command row and classification item atomically before archiving. On retry, an identical command ID and content means resume only the archive move. A moved file is never the sole evidence of acceptance. Conflicting content under an existing identity is an integrity failure.”
115. **[medium, U] “Never overwriting” inbox publication has no atomic collision rule.** A random six-hex suffix reduces collision probability but does not establish non-overwrite behavior, including archive destinations. **Add:** “Publish with an atomic no-replace operation. On EEXIST, generate a new filename and retry without modifying the existing file. Accepted and refused archive destinations also use no-replace publication or verify identical content before treating an existing destination as already completed.”
116. **[medium, U] Agenda edits and duplicate identities are underdefined.** Duplicate entry IDs, duplicate JSON keys, text changes within a period, and frequency changes can produce ambiguous command identities. **Add:** “Reject duplicate keys and IDs. An entry has an immutable revision digest over ID, text, and every_hours; command identity includes that digest and the period index. Editing an entry creates a new revision. Emit only the current period, never catch up missed periods, and document that behavior.”
117. **[medium] Approval destroys the provenance it is supposed to authorize.** Setting taint to owner changes “web-derived and approved” into “operator wrote it,” contradicting the taint definition. **Replace with:** “Taint is immutable provenance and is never reduced by approval. Store a separate approval record. Agent admission accepts external-taint items only when their current operative content has a valid operator approval.”
118. **[high, U] Approval is not bound to exact content and operation.** An item-level state change does not specify what happens if its lesson, request, target program, or permitted action changes later. **Add:** “Approval records the item ID, digest of operative fields, approved operation, operator identity, and timestamp. Any operative-field change invalidates approval. An approval for a lesson does not authorize different targets, additional requests, or descendant agent work.”
119. **[medium, U] Report and diagnostic escaping is incomplete.** one_line is required for status, but command reports include multiline model answers, titles, URLs, and error text without a defined terminal or Markdown escaping policy. **Add:** “Before terminal output, remove all control sequences except deliberate line breaks. Before Markdown rendering, escape text and validate link destinations; never render model-supplied image or HTML markup. Preserve raw evidence only in private bounded files, not directly in terminal output.”
120. **[medium, U] Secret handling omits several storage channels.** The listed screening points do not fully cover source titles, model-generated reasons and hypotheses, migration text, exception details, and raw call evidence written before later sanitization. **Add:** “Enumerate every persisted text field and capture file, with its admission, redaction, or refusal rule. Screen before persistence where the no-credential invariant applies. Raw traces require an explicit private-evidence policy and must never be copied into reports, prompts, bundles, or shared documents without screening.”

## Operator operations, recovery, storage, and validation

121. **[high, U] life-ctl apply: the tick lock does not exclude other repository writers.** Another agent or operator edit can occur after the live-file check but before application, violating preservation of others’ work. **Add:** “Apply requires a repository-wide writer reservation recognized by every platform writer. Under that reservation, capture and recheck all touched paths immediately before publication. If exclusive coordination is unavailable, refuse automatic live application and provide the patch for an operator-controlled maintenance window.”
122. **[high, U] life-ctl apply: unchanged touched files do not imply unchanged behavior.** Other dependencies may have changed since the patch was gated. --moved-base weakens the check further without requiring a fresh gate. **Add:** “Before live application, create an isolated snapshot of the current target tree, including relevant uncommitted content, apply the patch there, and rerun the complete gate. Bind the resulting approval to that exact target-tree digest. Any subsequent tree change invalidates the approval.”
123. **[high, U] Interrupted apply has no executable recovery protocol.** The journal preserves before-bytes, but revert refuses an unfinished apply and merely names a path. **Add:** “Provide recover-apply PATCH --confirm RECOVER. For every touched file, classify current bytes as before, intended-after, or unexpected. Restore only before/after-classified files according to the chosen recovery direction. Any unexpected file blocks recovery without overwriting it. Record every recovery action durably.”
124. **[high, U] Revert itself is not crash-journaled.** Restoring several files can fail halfway, after which some files match before-hashes and others after-hashes; the ordinary revert precondition may then reject continuation. **Add:** “Revert has its own durable intent and per-file completion records. Retrying an interrupted revert accepts files already restored to before-bytes and continues only files still matching after-bytes. Unexpected content stops the operation without modifying that file.”
125. **[high, U] Live-static application is not an atomic deployment.** Multi-file git apply can expose incompatible HTML, JavaScript, and CSS versions during application or after a crash. A warning does not prevent that state. **Add:** “Live-static changes are published through a versioned asset tree and one atomic active-version switch, or only while serving is explicitly quiesced. Applying multiple live-served files individually is not an accepted deployment method.”
126. **[high] LIFE.md §12, restore: the lock is released before restoration starts.** flock -n ... true only tests that the lock can be acquired, then immediately releases it. Subsequent moves and copies occur unlocked. **Replace with:** “Set STOP and disarm, stop both timer and service, then hold an exclusive tick.lock descriptor continuously across all database replacement, sidecar handling, integrity checks, and recovery bookkeeping. Release it only after the restored state is ready for reconciliation.”
127. **[high, U] Restore instructions omit benchmark and model executions.** They enumerate autogen runs only. Jobs launched after the backup can therefore continue without registry ownership after restoration. **Add:** “Recovery enumerates every LIFE-owned autogen run, benchmark job, model execution, launch intent, and transient scope using durable ownership labels. Unknown ownership is reconciled or cancelled before rearming. Listing only autogen runs is insufficient.”
128. **[high, U] Daily database copies are not a defined complete recovery set.** Restored rows can refer to releases, snapshots, bundles, approval records, and execution evidence not included in the backup. **Add:** “Publish a recovery manifest identifying both database snapshots and every required immutable state artifact by digest. Mark a backup complete only after that set is durable and verified. Document optional expired evidence separately; missing required artifacts prevent rearming.”
129. **[high, U] Backup creation does not reserve peak storage.** Writing .partial before retention can temporarily require an additional full database copy precisely when storage is already constrained. **Add:** “Before backup or migration backup, reserve the estimated complete output size plus 64 MiB safety margin on the destination filesystem. Remove only expired completed backups before starting, never the last verified backup. If reservation fails, open a storage notice and perform no partial copy.”
130. **[medium, U] Storage accounting does not define what bytes are counted.** Apparent size versus allocated size, hard-link deduplication, symlink traversal, separate filesystems, temporary captures, and platform-owned LIFE artifacts are unspecified. **Add:** “Report apparent and allocated bytes separately; enforce quotas using allocated blocks, deduplicated by (device, inode), without following symlinks. Account for every LIFE-owned local and remote artifact through an ownership inventory. Check free space independently on every filesystem receiving writes.”
131. **[high] Storage hold does not stop storage growth.** Inbox intake, agenda publication, backups, reports, and notices occur before the hold exit, while operator items are never dropped. Continued intake can exhaust disk despite the stated all-new-work hold. **Replace with:** “Storage hold disables all nonessential state-growing maintenance and new command acceptance. Leave unaccepted inbox files untouched and return an explicit storage refusal from command publication. Reserve emergency capacity for cancellation and recovery; log failure cannot prevent emergency control.”
132. **[medium, U] Retention omits division calls and abandoned temporary artifacts.** Division calls have item_id=NULL, so “14 days after its item ended” does not apply. Interrupted bundle, release, inbox, and clone preparations also have no collection rule. **Add:** “Call-directory retention is based on execution ended_at, independent of item presence. Temporary artifacts carry an owning intent ID. Remove abandoned preparations only after reconciliation proves no live owner; retain completed call evidence for 14 days and orphan diagnostics for seven days.”
133. **[medium, U] Permanent retention has no supported recovery from eventual capacity exhaustion.** Most state is never deleted, but the active store has a finite cap. The only explicit purge command targets refused inbox files. **Add:** “Provide an operator-invoked archive operation that exports and verifies completed, unreferenced records and artifacts, preserves lineage and identity tombstones, and then removes the archived active-store copies transactionally. Specify eligibility and retention per table. Capacity recovery must not require ad hoc SQL or manual deletion of authoritative state.”
134. **[medium, U] Status combines independently sampled registry and control state.** The registry transaction ends before control_state() is read. An arm/freeze change can make the combined display look like one coherent instant when it is not. **Add:** “Status reports registry_sampled_at, control_sampled_at, and a control generation. Read the control generation before and after the registry snapshot; if it changes, retry once or mark the result inconsistent. Do not label the combination a single execution snapshot.”
135. **[medium] bin/life-status.py: control inspection can escape the UNKNOWN handler.** L.control_state() runs outside the guarded block; an error hashing kit files can produce a traceback instead of the specified status result. **Replace with:** “Guard collection of all required status inputs, including control and kit integrity. An unavailable required input produces a structured UNKNOWN result and exit 1, without a traceback or an invented disarmed state. Always close the registry connection.”
136. **[medium, U] Seed recovery does not pin its initial inputs and phases.** An interrupted seed can resume after the source branch, HEAD, kit, or release material changes, producing a mixed installation. Detached HEAD behavior is also undefined. **Add:** “Before creating workspaces, persist a seed intent containing the kit digest, release manifest, source repository identity, branch name, and base commit. Resume only that intent. A changed input requires explicit seed-abort cleanup. Refuse detached HEAD unless an explicit branch and commit are supplied.”
137. **[high, U] retire --force: “cancel first” lacks a confirmation and timeout rule.** A cancellation acknowledgement or timeout must not allow retirement to discard execution ownership. **Add:** “Force-retire requests cancellation but does not retire until every owned execution is authoritatively terminal. After the bounded cancellation deadline, return refused with unresolved IDs and leave ownership intact. --force waives only the stated lifecycle restriction; it never waives unresolved-execution safety.”
138. **[medium] VALIDATE.sh and LIFE.md §13: the “every number” claim is not checked.** The validator compares embedded file copies and greps selected literals in life-tick.py; it does not compare the normative number table or protocol prose against constants. The impossible 3,600-second division requirement demonstrates the gap. **Replace with:** “Generate normative timing tables and protocol constants from one machine-readable definition. Validation compares every generated section and unit property byte-for-byte and checks cross-limit inequalities, including complete multi-step action budgets.”
139. **[medium, U] VALIDATE.sh: implementation imports are assumed inert rather than enforced.** It executes module top-level code from the CLI and omitted coordinator while promising no model, network, or external writes. A future top-level side effect would execute during “static” validation. **Add:** “Static validation imports only a separately audited pure-contract module. Any required implementation import runs in a supervised, network-denied, read-only environment with a private HOME. Side-effect attempts fail validation; they are never executed against the operational state or platform.”
140. **[high, U] LIFE.md §18 GAP 8: test names do not define admission criteria.** The list omits precise injection points, postconditions, retained-resource checks, and whether fake responses reproduce the real contract. **Add:** “Each admission test specifies initial state, injected failure boundary, expected rows/artifacts, expected notices, and forbidden side effects. Include the reproduced failures above, delayed submission after 404, negative cancel acknowledgements, leader-exit descendants, scope survival, full-disk STOP, immutable-gate checks, and real sandbox capability probes.
